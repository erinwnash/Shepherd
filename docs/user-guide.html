Shepherd User Guide

Shepherd is a resilient, self-healing orchestrator for batch coding agents (Claude Code, Antigravity, OpenAI Codex, Aider, and Gemini CLI). It manages queues of atomic work orders, executes verification gates in sandboxed OS containers, performs automated repair loops, meters quota across LLM pools, and distributes compute across local and LAN workers over mTLS.

Core Design Principles
Pure Go implementation (no cgo), Linux Tier 1 (Arch/Omarchy target), macOS Tier 1, Windows Tier 2. Single-writer daemon with SQLite WAL persistence, append-only SHA-256 hash-chained audit log, Bubblewrap process isolation, and Unix domain socket control plane with SO_PEERCRED verification.

Project Onboarding Wizard & launch.md Orchestration

Shepherd provides a built-in per-project onboarding wizard (shepherd onboard / shepherd wizard) that scaffolds all orchestration configuration and generates launch.md—a comprehensive mission directive that guides any supported agent CLI (Antigravity agy, Claude Code claude, OpenAI codex, opencode/local Ollama, aider, gemini, Hermes Agent hermes, or Pi pi) to inspect the project, establish Architecture Decision Records (ADRs), and decompose goals into verifiable chunk work orders.

Interactive Onboarding Wizard
Walks through project detection, language conventions, target CLI selection, and auto-launch options.
# Launch the interactive wizard
shepherd wizard

# Or explicitly pass the target project directory
shepherd onboard --dir /path/to/my-project --interactive
Automated Scaffolding & CLI Launch
Generate orchestration files and immediately launch the target agent CLI in one step.
# Auto-detect stack, write launch.md, and immediately launch Antigravity (agy)
shepherd onboard --cli agy --goal "Build Redis-backed event notification service" --launch

# Or preview generated files and the exact CLI launch command without writing to disk
shepherd onboard --dry-run

Scaffolded Orchestration Structure

When run, the wizard generates a production-ready orchestration layout inside the project directory:

  • shepherd.toml: Preconfigured with detected build/test gates, slot limits bounded by hardware safeguards, and repair chains.
  • launch.md: The autonomous onboarding prompt instructing the LLM agent CLI how to structure ADRs and work orders.
  • docs/adr/0001-record-architecture-decisions.md: Standard ADR template for recording foundational technical choices.
  • docs/plan/epic.md: High-level architectural roadmap and milestone definition.
  • docs/plan/S01/sprint.md: Sprint 1 scope, chunk inventory, and acceptance criteria.
  • .shepherd/prompts/coder.md & repair.md: Terse unattended coding and test repair guidelines.

Hardware Safeguards & Concurrency Control

To prevent local agents and compilers from freezing host machines or exhausting resources during onboarding and execution, Shepherd enforces strict hardware constraints:

  • GPU Worker Pinning: Multiworker routing limits local model agents to the number of detected physical GPUs (e.g. 1 video card = maximum 1 local worker slot), with CUDA_VISIBLE_DEVICES pinning.
  • RAM Safety Floor: Verifies that host available RAM remains above a safety reserve floor (default 4.0 GB) before provisioning additional slots.
  • Gate Execution Mutex: Serializes compiler and test suite invocations across worker slots so only one heavy test suite executes simultaneously, eliminating CPU cache thrashing.

Self-Verification via shepherd plan lint

The generated launch.md instructs the coding agent CLI to finalize its onboarding pass by running shepherd plan lint. The linter validates:

  • Strict YAML frontmatter compliance (ID, Title, Epic, Sprint, DependsOn, Files, Tests/NoTestsReason).
  • Mandatory new: prefix on any file created anew by a chunk.
  • Cycle-free Directed Acyclic Graph (DAG) dependencies.
  • Presence of mandatory Markdown sections: ## Goal, ## Out of scope, and ## Acceptance.

Quickstart: Launching and Testing

Follow these steps to build, initialize, test, and run Shepherd on your machine.

Step 1: Build the Binary

Compile Shepherd directly using the standard Go toolchain (pure Go, CGO-free):

# Build executable into build/shepherd
go build -o build/shepherd ./cmd/shepherd

# Verify compilation and binary SHA-256 digest
./build/shepherd version

Step 2: Run Preflight Diagnostics (Doctor)

Verify that your system has all required tools (Git, Bubblewrap, LLM CLIs):

./build/shepherd doctor

Output shows which agent runners (claude, agy, codex, aider, gemini) and sandbox tools are present on your PATH.

Step 3: Initialize a Project

Autodetect build and test runners, scan for available agent CLIs, and scaffold shepherd.toml:

./build/shepherd init

This generates the configuration file and creates the work order queue directory at docs/plan/.

Step 4: Lint Your Work Orders

Before executing anything, validate that all work orders in docs/plan/ have valid YAML frontmatter, declare test scopes, have no dependency cycles, and do not exceed file boundaries:

./build/shepherd plan lint

Step 5: Launch the Controller Daemon

You can run Shepherd in the foreground (for testing/development) or in the background:

# Foreground execution with real-time logs
./build/shepherd start -f

# Or launch daemon in background
./build/shepherd start

Step 6: Observe via the Interactive Terminal Dashboard (TUI)

Open a second terminal window to monitor active worker execution, quota gauges, and audit events:

# Live interactive dashboard
./build/shepherd dashboard

# Or single-shot headless snapshot (great for scripts or CI)
./build/shepherd dashboard --once

Running the Test Suite

Shepherd is developed test-first, with extensive unit, abuse-case, and end-to-end integration tests.

# Run all 27 package test suites with cached passes cleared
go test -count=1 ./...

# Run static analysis and lint checks
go vet ./...

# Run tests for a specific subsystem with verbose output
go test -v ./internal/controller/...
go test -v ./internal/sandbox/...
go test -v ./internal/lan/...
go test -v ./internal/tui/...
go test -v ./cmd/shepherd/...

Command Reference: Lifecycle & Steering

shepherd start [-f] [--root DIR] Lifecycle

Starts the queue execution coordinator. In background mode, spawns the single-writer daemon on the local Unix domain socket. Pass -f to run attached in the foreground with stdout logging.

shepherd status Observation

Queries the daemon socket and prints the current status: state (idle, running, paused, drain, locked), currently executing chunk, queue depth, active worker count, and pool spend.

shepherd pause / shepherd resume Steering

Pauses execution cleanly at the current step. resume signals the daemon to continue picking up pending chunks from the queue.

shepherd halt Emergency

Immediately kills the active agent process tree, rolls back the Git working tree cleanly to the pre-chunk commit, and places the chunk back into pending status.

shepherd drain <on|off> Quota

Toggles drain mode. In drain mode, Shepherd aggressively dispatches work to consume expiring quotas before weekly or daily reset windows, ignoring floor reserves.

shepherd lockdown / shepherd unlock Security

Halts all running processes immediately and locks the daemon. In lockdown, no new commands or chunks are processed until unlock is called with admin credentials.

Command Reference: Queue & Work Orders

shepherd queue ls [--status STATUS] Queue

Lists all loaded chunks in dependency order with their title, tier, review level, attempt counter, and execution status (pending, running, done, blocked, held, skipped).

shepherd queue <skip|retry|hold|release|diff|approve|reject|pin> <chunk-id> Steering & Review

Performs live manual queue steering and human-in-the-loop review for HIGH risk chunks:

  • diff <id>: Displays the stored unified diff patch for a held chunk before committing.
  • approve <id>: Applies the held patch, stages only non-internal files, commits with Approved-By: operator, and marks the chunk done.
  • reject [--reason MSG] <id>: Discards the held patch, resets the worktree cleanly, and marks the chunk blocked.
  • skip: Marks chunk as skipped without failing dependents.
  • retry: Resets attempt count and returns a blocked chunk to pending.
  • hold: Pauses execution of a specific chunk (e.g. pending manual human sign-off).
  • release: Releases a held chunk back to the scheduler.
  • pin: Prioritizes chunk to run at the very front of the queue next.

shepherd plan lint [--root DIR] [--plan DIR] [--max-files N] Validation

Static pre-execution linter. Enforces work order schema integrity: checks that referenced files exist or are tagged new:, validates ADR references, ensures declared test targets exist, and detects circular dependency graphs.

shepherd plan split [--parts N] [--write] <chunk.md> Decomposition

Partitions an oversize work order across file boundaries into sequential sub-chunks (01A.1, 01A.2) with automatic dependency chaining and markdown serialization.

shepherd plan test-first [--write] [--out-dir DIR] <chunk-file-or-id> TDD Anti-Cheat

Decomposes a chunk into an automated two-stage Test-Driven Development (TDD) pair: <id>.spec (test specification & fixture authoring) and <id>.impl (production implementation). The implementation stage strictly mounts the test files as read-only (read_only_tests: true); any modification, weakening, or deletion of test files is instantly blocked by the verification scope gate, preventing LLM test-tampering.

shepherd plan migrate --from bold-lines [--out DIR] Migration

One-shot migrator for legacy work orders, converting them into validated YAML frontmatter Markdown files.

Command Reference: Config & Quota Management

shepherd config <show|set|reload> Config

Inspects or updates runtime configuration. config set <key> <value> applies live overrides stored in SQLite without restarting the daemon; config reload re-reads shepherd.toml.

shepherd quota <show|set-floor|set-reserve|tier> Quota

Inspects usage percentages and headroom across provider pools (Claude, Antigravity, OpenAI). Manage weekly reserve floors to prevent automated runs from consuming human developer quotas.

Cost & Token Budget Circuit Breakers & Pre-Commit Secret Scanner ([policy] & [[gates]]) FinOps & DLP

Prevent runaway API spend and accidental secret commits with built-in budget circuit breakers and pre-commit secret scanning: 

[policy]
max_chunk_cost_usd = 2.50    # Block chunk immediately if cumulative attempt spend exceeds $2.50
max_sprint_cost_usd = 25.00  # Pause daemon & alert operator if sprint spend exceeds $25.00
sandbox_backend = "podman"   # Optional: "bwrap", "podman", or "docker"
container_image = "golang:1.22"

[[gates]]
name = "secrets"
builtin = "secrets"          # Scans modified worktree files for AWS, Anthropic, OpenAI, GitHub, Slack & PEM keys
hard = true

Operator Notifications ([notify] in shepherd.toml) Alerting

Shepherd automatically alerts operators via Slack, Discord, or desktop popups when runs need attention: 

[notify]
events = ["chunk_held", "queue_blocked", "sprint_done", "quota_critical"]
slack_webhook_url = "https://hooks.slack.com/services/..."
discord_webhook_url = "https://discord.com/api/webhooks/..."
desktop = true  # notify-send on Linux, AppleScript osascript on macOS
Dispatches instantly when a high-risk chunk is held for manual sign-off, when an adapter blocks, or when all sprint chunks complete.

Flaky Test Quarantine & Delta Attribution ([verify] in shepherd.toml) Reliability

Eliminate gate failures caused by legacy flaky tests or pre-existing bugs in evolving codebases: 

[verify]
flake_retries = 3      # Rerun failed test up to 3 times before declaring gate failure
base_commit_delta = true  # Check base commit if a test fails
When base_commit_delta = true and a test gate fails, Shepherd executes the identical test target against the base commit (HEAD) in an isolated, detached worktree. If the test also fails on the base commit, Shepherd recognizes the failure as pre-existing, records a test.quarantined audit log event, and allows the chunk to proceed without penalizing model quota.

Worker Slot Multiplexing & Hardware Safeguards ([slots] in shepherd.toml) Performance & Safety

Safely leverage multi-core developer workstations without branch sprawl, RAM exhaustion, or UI lag: 

[slots]
max_slots = 2         # Bounded pool of detached worktree directories (.shepherd/slots/slot-N)
min_free_ram_gb = 4.0 # Safety floor: refuse new slot if host RAM falls below 4 GB
max_gpu_workers = 1   # Strict GPU concurrency limit (auto-detected via nvidia-smi -L)
desktop_priority = true # Wraps all agent & gate subprocesses with nice -n 10 and ionice -c 3
  • Zero Permanent Branches: Slots are mounted on detached HEAD. Patches are extracted via git diff and applied directly to main with serial integration.
  • GPU Concurrency Gate: Limits local GPU inference (Ollama, vLLM, OpenCode) to the physical GPU count (e.g., 1 GPU = 1 local agent) to avoid display driver crashes.
  • Gate Execution Mutex: Serializes verification gate executions (Concurrency = 1) so only one test suite runs at a time, eliminating CPU cache thrashing and false test timeouts.
  • Desktop Protection: Agents run at idle I/O priority (ionice -c 3) and low CPU priority (nice -n 10), guaranteeing that editors and terminals remain responsive.

Dynamic Tier Escalation & Cascading Repair ([repair] in shepherd.toml) Repair Engine

Adaptive multi-round repair with intelligent model escalation and cross-model diagnostic context injection: 

[repair]
chain = ["haiku:1", "sonnet:2", "opus:1"]
mechanical_fix = { tier = "haiku", max_errors = 3, codes = ["TS2304"] }
  • Attempt 1: Initial chunk execution on the assigned cost-optimized tier.
  • Attempt 2 (Repair): If failures are mechanical (simple typing/syntax), keep low-cost tier; if failures are semantic (test assertion failures, panics, logic errors), dynamically escalate to a frontier model (Sonnet / GPT-4o / Gemini Pro).
  • Attempt 3 (Final Review): Escalate to the top tier with Cross-Model Diagnostic History injected into the prompt, summarizing exactly why prior models failed so the frontier model addresses the root cause directly.

AST Repo Map & Golden Example Pre-Injection Context Optimization

Accelerate agent execution and reduce token consumption by pre-injecting structural repository intelligence:

  • AST Symbol Indexing: Automatically parses and formats top-level exported types, structs, interfaces, and function signatures across Go (via native go/ast), TypeScript, and Python files in the target package.
  • Golden Example Pre-Injection: Automatically locates a recently completed commit in Git history (feat(...)) that touched similar directories, extracting its diff snippet to demonstrate coding conventions, project idioms, and testing patterns.
  • Zero Exploration Overhead: Eliminates the 3–5 initial exploratory tool calls that agent CLIs typically burn to discover project interfaces.

Command Reference: LAN Workers & mTLS

Shepherd coordinates multiple secondary worker machines across a local network using mutual TLS 1.3 with a private root Certificate Authority.

shepherd worker add [--addr HOST:PORT] Primary Node

Generates a one-time 128-bit pairing token with a 10-minute expiration and displays the pairing connection string for the remote worker.

shepherd worker join <pairing-string> Worker Node

Executes on the worker machine: verifies the primary node's pinned CA public-key hash, sends an HMAC-SHA256 authenticated CSR, receives a 7-day signed client certificate, and joins the worker pool.

shepherd worker ls Worker Pool

Lists all paired worker nodes, public-key fingerprints, roles, heartbeat timestamps, and current state.

shepherd worker revoke <worker-id> Security

Instantly revokes a worker certificate in SQLite and drops active TCP/TLS connections mid-session (STRIDE S4 mitigation).

shepherd pr [--sprint ID] [--create] [--draft] [--base main] Pull Requests

Generates a structured Markdown Pull Request summary table containing all sprint work orders, assigned tiers, worker attributions, and total USD/token telemetry. Pass --create to automatically open the Pull Request via the GitHub CLI (gh pr create).

shepherd service <install|uninstall|status> System Service

Installs Shepherd as a native unprivileged user background daemon:

  • Linux: Configures and enables systemd user unit (~/.config/systemd/user/shepherd.service).
  • macOS: Configures and loads launchd user agent (~/Library/LaunchAgents/ai.shepherd.daemon.plist).

shepherd retro [--db PATH] [--format md|table] Analytics

Generates sprint retrospective analytics aggregating completed vs blocked chunks, attempt ratios, quota spend by pool, and average cost per chunk.

Command Reference: Diagnostics & Auditing

shepherd dashboard [--once] [--tab <overview|logs|top|gpu|nvtop>] TUI Dashboards

Interactive ANSI terminal user interface with 5 switchable dashboards:

  • [1] OVERVIEW: Live quota gauges, active worker execution transcript, queue status, and alerts.
  • [2] LOGS: Real-time streaming SHA-256 hash-chained audit ledger, daemon state transitions, and live subprocess logs.
  • [3] TOP: Live system CPU, RAM, load averages, and top process monitor. Press [x] or [Enter] to launch full-screen interactive top.
  • [4] LLAMAGPUTOP: Real-time GPU & LLM inference monitor (integrated from tools/llamagputop/) tracking VRAM, GPU compute, temperature, power, and active llama.cpp model context. Press [x] or [Enter] for interactive view.
  • [5] NVTOP: Live NVIDIA/AMD GPU engine and process usage table. Press [x] or [Enter] to launch full-screen interactive nvtop.
Navigation & Controls:
  • 1, 2, 3, 4, 5: Switch directly to any dashboard tab.
  • Tab / [ / ]: Cycle sequentially through all 5 dashboard views.
  • x / Enter: Launch full-screen interactive tool (top, llamagputop, nvtop) with seamless raw mode restore upon exit.
  • p (pause), r (resume), h (halt), d (drain), l (lockdown), u (unlock), q (quit).

shepherd web [--addr HOST:PORT] [--port PORT] Browser Web UI

Zero-dependency embedded web dashboard and visual DAG dependency graph:

  • Interactive Visual DAG: Real-time rendered dependency graph with color-coded chunk nodes: Green (Done), Blue (Running), Orange (Held), Red (Blocked), Gray (Pending). Click any node to inspect file targets, view held unified diffs, and trigger Approve, Reject, Release, Retry, or Skip actions.
  • Remote Daemon Controls: Mobile & tablet friendly buttons to Pause, Resume, Drain, and Halt runs directly from the browser, protected by CSRF Origin / Sec-Fetch-Site verification and optional SHEPHERD_WEB_TOKEN bearer authentication.
  • Live Event Streaming: Server-Sent Events (SSE) stream audit logs and status updates to connected clients in real time.

shepherd audit [--tail N] Audit Log

Reads the immutable, append-only SHA-256 hash-chained event log. Verifies cryptographic chain continuity back to the Genesis Hash, verifying that no historical states or decisions have been tampered with.

Work Order Specification (`docs/plan/`)

Each chunk in Shepherd is defined as an individual Markdown file containing strict YAML frontmatter:

---
id: 01A
title: User Authentication Middleware
sprint: S01
depends_on: []
review: LOW              # LOW, MEDIUM, or HIGH
effort: S                # S, M, or L
status: pending          # pending, running, done, blocked, skipped, held
files:
  - internal/auth/middleware.go
  - new:internal/auth/middleware_test.go
tests:
  - internal/auth/middleware_test.go
no_tests_reason: ""      # Required if tests is empty
---

## Goal
Implement bearer token authentication middleware with timing-safe comparison.

## Scope
Validate Authorization headers against SQLite active sessions. Reject expired tokens.

## Done when
- Unit tests in internal/auth/middleware_test.go pass with 100% branch coverage.
- Content-loss gate reports zero unexplained line deletions.
File Scope Enforcement
The files: list is mandatory. Agents are strictly confined to modifying only files explicitly declared in the frontmatter. New files must be tagged with new:. The scope gate rejects any patch attempting edits outside declared boundaries.

Security & OS Containment Model

Shepherd implements multi-layered OS and container containment to safeguard host systems when executing agent code and verification gates:

  • Bubblewrap (`bwrap`) on Linux: Runs agent subprocesses in isolated mount namespaces. Masks ~/.shepherd, $HOME, control sockets, and blocks network access via --unshare-net for verification gates while permitting outbound API traffic only for cloud adapters that declare RequiresNetwork.
  • macOS Seatbelt (`sandbox-exec`): Escapes all profile paths against SBPL injection, restricts file writes strictly to the active worktree root, and explicitly blocks file reads on .shepherd, control sockets, and sensitive $HOME credential directories (~/.ssh, ~/.aws, ~/.gnupg, ~/.kube, ~/.config/gcloud).
  • Rootless Container Sandbox (`podman` / `docker`): Optional container isolation backend (sandbox_backend = "podman" | "docker") running with --cap-drop=ALL, --security-opt=no-new-privileges, --read-only rootfs, and isolated tmpfs mounts over masked state directories.
  • Environment Scrubbing (`ScrubEnv`) & Explicit Provider Allowlists: Filters out sensitive host environment variables (SSH_AUTH_SOCK, AWS_*, GITHUB_TOKEN, KUBECONFIG, SHEPHERD_SOCKET) while forwarding only the specific provider API key required by the active adapter.
  • Constant-Time Token Auth & Web CSRF Protection: Control socket bearer tokens are verified with subtle.ConstantTimeCompare (never matching empty unset env vars), and the embedded Web UI enforces Origin / Sec-Fetch-Site CSRF checks plus optional SHEPHERD_WEB_TOKEN authentication.
  • Pre-Commit Secret Scanner & Redaction Sink: The built-in secrets gate blocks commits containing leaked credentials, while redact.Sanitize scrubs API keys, tokens, and private keys before persisting transcripts to SQLite, audit logs, or webhook notifications.
